# ERP 系统设计文档（MTO 组装/贸易型企业）

> 日期：2026-08-20
> 状态：待用户审阅
> 项目代号：erp

## 1. 背景与目标

### 1.1 业务背景
一家按订单生产（MTO）的组装/贸易型企业，面向海外客户。核心业务流程：

> 海外客户下订单（成品）→ 按成品拆算零件需求 → 采购向供应商下单 → 供应商送货、仓管收货入库 → 生产组长按需领料 → 每日打包成品入库 → 到期出货 → 外贸跟踪运输进度 → 财务对账。

### 1.2 现状与痛点
- 各角色各自维护 Excel，靠微信/口头传递信息，形成信息孤岛。
- 老板不了解订单进度，需要反复询问员工。
- 员工在 Excel 与微信之间来回，效率低下。

### 1.3 目标
- 以"销售订单"为主线，串联采购、库存、生产、出货、财务全流程。
- 老板打开系统即可看到每张订单的进度、成本、周期、收付款。
- 各角色录入一次，信息自动流转，减少重复与口头确认。
- 第一版快速上线、稳定运行，架构保留未来扩张能力。

### 1.4 成功标准
- 老板无需询问员工即可查看任意订单的实时进度与成本。
- 库存账实一致，出入库全部留痕。
- 客户收款（无定金、出货后 2 个月付款）与供应商付款均有账期提醒，不漏收不漏付。
- 系统在公司局域网内稳定运行，数据每日自动备份。

## 2. 范围

### 2.1 第一版包含的模块
| # | 模块 | 说明 |
|---|------|------|
| 1 | 基础资料 | 成品/零件档案、BOM、供应商、海外客户 |
| 2 | 销售订单 | 海外客户下单：成品、数量、交期、单价 |
| 3 | 采购管理 | 按订单自动拆算零件需求 → 生成采购单 → 收货 |
| 4 | 库存管理 | 收货入库、领料出库、成品入库、实时库存台账 |
| 5 | 生产管理 | 生产组长领料、每日成品入库、生产进度 |
| 6 | 出货管理 | 到期出货、运输节点跟踪 |
| 7 | 财务对账 | 供应商付款、客户收款、每单成本与利润、账期提醒 |
| 8 | 老板看板 | 订单进度、成本、周期、收付款一屏可见 |

### 2.2 第一版明确不做（YAGNI）
- 手机 App（架构预留 API，后续可加）。
- 供应商/客户自助登录门户（第一版由内部录入）。
- 复杂财务总账、多币种自动汇率。
- 精细生产排程、员工工时统计。
- 多公司/多仓库组织架构。

### 2.3 角色与权限（第一版 6 个角色）
老板、采购、仓管、生产组长、外贸、财务。每人只看到自己负责的界面，权限在服务端强制校验。

## 3. 架构

三层架构，全部部署在公司一台常开电脑上，零云成本：

```
各角色浏览器
    │ 局域网 HTTP
    ▼
前端 React（按角色渲染界面）
    │ REST API
    ▼
后端 Node.js + TypeScript（业务逻辑、权限校验、计算）
    │
    ▼
PostgreSQL 数据库（所有数据）
```

- 前端：React，桌面浏览器优先，界面简单直接。
- 后端：Node.js + TypeScript，模块化，接口化。
- 数据库：PostgreSQL，支撑多人并发写入与后续数据增长。
- 部署：常开电脑，开机自启，局域网访问。

### 3.1 组件划分
业务模块：订单、采购、库存、生产、出货、财务、看板。
贯穿模块：权限（认证 + 授权 + 审计）。

每个模块单一职责、通过清晰接口交互，可独立理解与测试。

## 4. 数据流（订单生命周期）

```
① 外贸录入海外订单（成品、数量、交期、单价）
    ↓
② 系统按 BOM 自动拆算零件需求（规则 2：扣现有库存，只采购缺口）
    ↓
③ 采购生成采购单，发给供应商
    ↓
④ 供应商送货 → 仓管收货入库（零件库存↑，自动记账）
    ↓
⑤ 生产组长按需领料（零件库存↓，自动记账）
    ↓
⑥ 每日打包成品入库（成品库存↑）
    ↓
⑦ 到期出货（成品库存↓），外贸更新运输节点
    ↓
⑧ 财务录入供应商付款、客户收款，系统算每单成本/利润
    ↓
⑨ 老板看板：每张单的进度、成本、周期、收付款
```

原则：
1. 一切单据挂到销售订单主线，任意订单可追溯全貌。
2. 库存变动自动记账、留痕。
3. 权限在服务端强制校验。

## 5. 数据模型

### 5.1 实体
- 组织/人员：客户、供应商、用户（挂角色）。
- 物料：成品、零件、BOM（成品→零件用量）。
- 单据：销售订单、采购单、收货单、领料单、成品入库单、出货单、付款单、收款单。
- 库存：库存台账（当前数量）+ 出入库流水（谁、何时、因哪张单、进出多少）。

### 5.2 关系
```
客户 ──▶ 销售订单 ──▶ 订单明细(成品×数量)
                     │
        ┌────────────┼───────────────┐
        ▼            ▼               ▼
   BOM拆算零件   领料/成品入库/出货   收款(客户付款)
        │
        ▼
   采购单 ──▶ 采购明细(零件×数量) ──▶ 供应商
        │
        ├──▶ 收货单(入库)
        └──▶ 付款(供应商付款)
```

### 5.3 核心业务规则
- **BOM 拆算（规则 2）**：采购需求 = 订单成品数量 × BOM 零件用量 − 当前可用库存，只采购缺口；允许采购人工调整。
- **账期**：客户无定金、出货后 2 个月付款；系统按出货日期自动生成应收账期与提醒。
- **成本核算**：每单成本 = 零件采购成本 + 可登记的其他费用；利润 = 客户收款 − 成本。

## 6. 界面设计

- 老板：首页看板（订单进度条、成本、利润、周期、应收/应付与逾期）、报表页（成本利润汇总、现金流概览）。
- 外贸：销售订单录入/修改、出货管理（运输节点）、客户对账。
- 采购：零件需求页（自动算好缺口）、生成采购单、供应商跟催。
- 仓管：收货入库、领料出库、成品入库、库存查询。
- 生产组长：领料申请、生产进度（每日成品入库）、订单进度查看。
- 财务：供应商付款、客户收款、成本利润、账期提醒（未来 30/60 天应收应付清单）。

界面原则：简单直接、一眼看懂，每个角色打开即常用功能，无需培训。

## 7. 错误处理

- 输入即时校验：数量非负、必填完整、日期合法。
- 库存不允许录成负数；不足时明确提示。
- 并发防护：防止重复提交与数据冲突。
- 操作失败给出明确中文提示；关键写入使用事务，不留半截数据。

## 8. 测试策略

- 核心计算逻辑重点测试：BOM 拆算（规则 2）、库存增减、账期计算、成本利润。
- 权限测试：越权访问被拒绝。
- 每次修改后核心测试必须通过。

## 9. 部署与备份

- 部署：公司常开电脑，后端 + 数据库安装，配置开机自启；局域网内浏览器访问。
- 备份：每日凌晨自动备份 PostgreSQL；备份存放于另一块盘/另一台机器；提供一键恢复。
- 日志：记录关键操作，便于排错与审计。
